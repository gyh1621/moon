# Private diagnostic reports

Settings → Maintenance → Diagnostic report sends a report directly to a new issue in the private `gyh1621/moon-diagnostics` repository. The public Moon repository and release downloads remain public. Uploads happen only when the user taps Upload diagnostic report; there is no preview or automatic telemetry.

Create a GitHub fine-grained personal access token selecting only `moon-diagnostics`, with **Issues: Read and write** and the implicit **Metadata: Read** permission. Enter it in the masked GitHub token field on the reader. The token is saved locally under `.moon/settings/diagnostics.lua`; it is never bundled with the plugin or included in a report. GitHub requires the token owner's access to this private repository.

Before reading a report, Moon makes an uncached authenticated request to verify the exact repository identity, private visibility and enabled issues. It refuses to continue if these checks fail. Recognizable GitHub token strings and the configured token are removed from report content. Other log content is uploaded as recorded; this does not promise to remove arbitrary secrets.

Each issue contains:

- Moon and KOReader versions, device model, UTC capture time, current battery capacity and charging state.
- The readable **Battery Statistics** report generated by KOReader's already-loaded battery statistics plugin, including awake, sleeping, charging and total discharge durations, percentage changes, hourly rates and estimates. Moon accumulates the current interval, just as opening that screen does, and flushes only its dedicated statistics file. It never resets the history.
- Up to the first 4 KiB of KOReader's `settings/battery_stats.lua`, containing the saved counters and state timestamps. KOReader stores durations in its internal microsecond units. The readable report converts them to durations and rates. A disabled/unavailable statistics plugin is reported explicitly; any saved counters are still included.
- The latest 12 KiB each of KOReader's `crash.log` and Moon's `.moon/book.log`. Missing/empty files and truncation are identified. Non-UTF-8 content is represented as Base64 after token removal.

Battery Statistics measures aggregate percentage changes during awake/sleep/charge intervals. It cannot attribute power use to individual plugins or processes. Sleep and awake hourly rates can help identify where drain occurs, while the logs provide context. Reader statistics are needed before diagnosing a particular device's drain.

File reads run in a worker; network requests use Moon's asynchronous HTTP client. Repeated taps are suppressed while a report is uploading. Success shows the issue number and link. If a POST result is uncertain, check the private repository before sending again: Moon does not retry automatically because the issue might already exist.

No books, databases or other settings files are uploaded. Collecting a report does not enable ongoing debug logging. An empty report is rejected when neither logs nor battery statistics are available.
